# 必须遵循的代码通用开发原则
## 核心设计原则
- KISS原则：保持简单愚蠢，避免过度复杂化
  - 模块化、组件化：高内聚、低耦合的架构设计
  - DRY原则（Don't Repeat Yourself）：避免重复代码，提取公共逻辑
  - YAGNI原则（You Aren't Gonna Need It）：不要过度设计，只实现当前需要的功能
  - 单一职责原则：每个模块/函数只做一件事
## 代码质量原则
  - 可读性优于简洁性：代码是写给人看的
  - 明确优于隐晦：显式声明胜过隐式猜测
## 协作与维护原则
  - 文档同步：代码即文档，注释解释为什么而非是什么
  - 代码复用：优先使用共享组件和工具库

## 项目核心开发规范

### NestJS 开发规范
- **模块化架构**: 严格遵循 NestJS 模块化设计，每个功能独立模块
- **依赖注入**: 合理使用 DI 容器，避免硬编码依赖关系
- **装饰器使用**: 正确使用 `@Controller`、`@Service`、`@Injectable` 等装饰器
- **中间件和守卫**: 合理使用中间件、守卫、拦截器处理横切关注点
- **配置管理**: 使用 `@nestjs/config` 管理环境配置，严禁硬编码

### TypeORM 数据库规范
- **实体设计**: 使用装饰器定义实体，遵循数据库设计规范
- **🚨 CRITICAL - Comment 字段必须规范**:
  - 每个 `@Entity()` 装饰器必须包含 `comment` 参数，描述表的用途
  - 每个 `@Column()` 装饰器必须包含 `comment` 参数，描述字段含义
  - comment 使用中文，清晰描述字段用途和可能的枚举值
  - 示例: `@Entity('users', { comment: '用户基础信息表' })`
  - 示例: `@Column({ type: 'varchar', length: 50, comment: '用户姓名，最大50个字符' })`
  - 遵循可读性优于简洁性原则，让代码更易理解和维护
- **关系映射**: 正确定义 OneToOne、OneToMany、ManyToMany 关系
- **查询优化**: 合理使用 QueryBuilder，避免 N+1 查询问题
- **事务处理**: 重要操作必须使用事务保证数据一致性
- **迁移管理**: 使用 TypeORM 迁移管理数据库结构变更

### API 设计规范
- **RESTful 设计**: 严格遵循 RESTful API 设计原则
- **状态码规范**: 正确使用 HTTP 状态码（200、201、400、401、403、404、500 等）
- **数据验证**: 使用 class-validator 进行请求数据验证
- **错误处理**: 统一的异常处理机制，返回标准化错误响应
- **API 文档**: 使用 Swagger 装饰器自动生成 OpenAPI 文档

### TypeScript 严格模式
- 所有函数参数和返回值必须显式类型定义
- 严格遵循 `noImplicitAny`、`noUnusedLocals`、`strictNullChecks` 等配置
- 构建前必须通过类型检查，确保 `pnpm --filter backend build` 成功

### 依赖管理
- **安装位置**: 所有后端依赖安装到 `backend` 工作区
- **正确命令**: `pnpm --filter backend add <package>`
- **路径别名**: 使用绝对路径导入，避免相对路径嵌套

### 安全和性能规范
- **数据验证**: 严格验证所有输入数据，防止注入攻击
- **身份认证**: 使用 JWT 或 Session 进行用户认证
- **权限控制**: 实施基于角色的访问控制（RBAC）
- **日志记录**: 重要操作必须记录日志，便于问题排查
- **性能监控**: 关键接口添加性能监控和限流

## 五阶段专业工作流程

### 阶段 1: 深度任务分析
**目标**: 全面理解业务需求，分析现有后端架构
**执行步骤**:
1. 详细解析用户需求，识别业务逻辑和数据流
2. 阅读项目索引文档`docs/doc_index.md`，并从中找到相关文档进行阅读和查找必要的信息。
2. 使用 Read/Glob 工具分析相关现有代码和数据库结构
3. 识别服务依赖、数据模型和接口设计
4. 评估任务复杂度、性能要求和安全风险
5. 确定需要新建或修改的模块、服务、实体范围

### 阶段 2: 技术架构设计
**目标**: 制定技术实现方案，确保架构合理性，必须遵循代码通用开发原则
**执行步骤**:
1. **🚨 CRITICAL - Shared包类型设计优先**:
   - 首先检查shared/types/中已有的类型定义
   - 明确区分前后端共用类型 vs 后端特有类型
   - 前后端共用类型（API请求响应、实体接口、枚举等）必须放在shared包
   - 后端特有类型（内部业务逻辑、数据库操作接口等）才放在backend中
   - 避免重复定义，确保前后端类型一致性
2. 系统设计：确定模块结构、服务层次、数据库设计
3. API 设计：接口规范、请求响应格式、错误处理策略
4. 数据模型：实体关系、索引设计、查询优化
5. 安全方案：认证授权、数据验证、攻击防护
6. 性能优化：缓存策略、数据库优化、接口性能

## 错误处理和质量保证

### 常见问题预防
- **数据库连接**: 确保数据库配置正确，连接池合理设置
- **类型错误**: 严格定义 DTO、Entity 和 Service 接口类型
- **异常处理**: 使用 NestJS 异常过滤器统一处理错误响应
- **性能问题**: 注意查询优化，避免 N+1 问题和大量数据加载
- **🚨 Comment 缺失**: 新建实体时忘记添加 comment 说明，导致代码可读性差，违反项目规范

### 测试策略
- **单元测试**: 核心业务逻辑必须有单元测试覆盖
- **集成测试**: 重要 API 接口需要端到端测试
- **数据库测试**: 使用测试数据库，避免影响开发数据

### 回滚策略
- 保持小步提交，便于问题定位和回滚
- 数据库迁移必须可逆，提供 down 方法
- 关键功能上线前必须有回滚预案
