# 必须遵循的代码通用开发原则
## 核心设计原则
- KISS原则：保持简单愚蠢，避免过度复杂化
  - 模块化、组件化：高内聚、低耦合的架构设计
  - DRY原则（Don't Repeat Yourself）：避免重复代码，提取公共逻辑
  - YAGNI原则（You Aren't Gonna Need It）：不要过度设计，只实现当前需要的功能
  - 单一职责原则：每个模块/函数只做一件事
## 代码质量原则
  - 可读性优于简洁性：代码是写给人看的
  - 明确优于隐晦：显式声明胜过隐式猜测
## 协作与维护原则
  - 文档同步：代码即文档，注释解释为什么而非是什么
  - 代码复用：优先使用共享组件和工具库

## 项目核心开发规范

### TypeScript 严格模式
- 所有组件 props 必须显式类型定义，杜绝 `implicit any`
- 严格遵循 `noImplicitAny`、`noUnusedLocals` 等配置
- 构建前必须通过类型检查，确保 `pnpm --filter frontend-app build` 成功

### Tailwind CSS v4 规范
- **核心原则**: 本项目使用 Tailwind CSS v4，配置方式与 v3 完全不同
- **配置位置**: 所有配置在 `frontend-app/app/globals.css` 中通过 `@theme` 指令完成
- **禁止**: 不得使用 `tailwind.config.js` 或 `tailwind.config.ts`
- **入口点**: `@import "tailwindcss";` 绝对不能删除
- **颜色规范**: 严禁硬编码颜色，必须使用项目预定义的 CSS 变量

### shadcn/ui 组件使用策略
- **优先级**: shadcn/ui > 自定义组件 > 第三方组件库
- **安装命令**: `cd frontend-app && npx shadcn@latest add <component>`
- **自定义方式**: 通过修改组件的 `cva` 配置添加新 `variant`，而非外部覆盖
- **设计一致性**: 确保所有 UI 元素基于 shadcn/ui 设计规范

### 图标和资源规范
- **图标库**: 必须使用 Lucide React，按需导入
- **颜色设置**: 使用 CSS 变量，如 `className="text-[var(--primary-color)]"`
- **图片资源**: 本地化存储，使用 `next/image` 组件，遵循 Next.js 15 规范

### 依赖管理
- **安装位置**: 所有前端依赖安装到 `frontend-app` 工作区
- **正确命令**: `pnpm --filter frontend-app add <package>`
- **路径别名**: 使用 `@/` 别名引用 `frontend-app/` 目录

### NextJS最佳实践
- **组件化**：组件化，组件路径遵循Nextjs最佳实践，就近原则 _components。不要堆在一个page里面
