# PRD: 用户登录系统

## Executive Summary

本PRD定义了智赢AI营销平台(frontend-app)的用户登录系统，为5000名企业用户提供安全、高效的身份认证服务。系统基于JWT认证机制，支持邮箱密码登录，集成用户角色权限管理，确保平台安全性和用户体验。

核心价值：
- 为企业用户提供安全可靠的访问控制
- 支持多层级用户角色权限管理
- 保障5000用户规模的高性能认证服务
- 无缝集成现有技术架构

## Problem Statement

### 当前痛点
智赢AI营销平台需要一个完整的用户身份认证系统来：

1. **访问控制缺失**：平台缺乏用户身份验证机制，无法区分和管理不同用户
2. **安全风险**：没有统一的认证系统，存在未授权访问的安全隐患
3. **权限管理需求**：企业用户需要不同的权限等级来访问不同功能模块
4. **会话管理**：需要安全的会话管理机制，防止会话劫持和未授权访问

### 业务影响
- 无法提供个性化的企业级服务
- 存在数据泄露和未授权访问风险
- 无法有效管理用户权限和功能访问
- 影响平台的商业化进程

## User Stories

### 主要用户画像
**企业用户**（主要目标用户）
- 身份：企业营销负责人、市场经理、运营人员
- 规模：预计5000名用户
- 技术水平：一般（非技术背景）
- 使用场景：日常办公，使用AI营销工具提升业务效率

### 核心用户故事

**作为企业用户，我希望：**

1. **安全登录**
   - 使用邮箱和密码登录系统
   - 登录过程简单快捷，不超过30秒
   - 系统记住我的登录状态，避免频繁重新登录
   - 收到登录失败的明确错误提示

2. **权限管理**
   - 根据我的角色级别访问相应的功能模块
   - 在权限不足时收到友好的提示信息
   - 了解自己的当前权限等级和可用功能

3. **会话安全**
   - 在长时间不活跃后自动退出登录保护账户安全
   - 在其他设备登录时有安全提醒
   - 主动退出登录功能

### 详细用户旅程

#### 登录流程
```
1. 用户访问 frontend-app 应用
   ↓
2. 系统检测到未登录状态，重定向到登录页面
   ↓
3. 用户输入邮箱和密码
   ↓
4. 前端验证输入格式，发送登录请求到后端
   ↓
5. 后端验证凭据，返回JWT token和用户信息
   ↓
6. 前端存储认证信息，重定向到dashboard首页
   ↓
7. 用户成功访问应用内功能
```

#### 权限检查流程
```
1. 用户尝试访问某个功能模块
   ↓
2. 系统检查JWT中的用户角色和权限
   ↓
3a. 权限充足：正常访问功能
3b. 权限不足：显示权限不足提示，建议升级
```

## Requirements

### Functional Requirements

#### FR-001: 用户认证
- **登录方式**：邮箱+密码
- **认证流程**：
  - 支持邮箱格式验证（包含@符号和有效域名）
  - 密码强度验证（至少8位，包含数字+字母+特殊字符）
  - 登录失败防暴力破解保护（连续5次失败锁定账户10分钟）
  - JWT token生成和验证

#### FR-002: 会话管理
- **Token管理**：
  - Access Token有效期：15分钟
  - Refresh Token有效期：7天
  - 自动刷新机制避免频繁重新登录
- **会话保护**：
  - 安全的token存储（HttpOnly Cookie推荐）
  - 跨站请求伪造(CSRF)保护
  - 会话过期自动跳转登录页

#### FR-003: 用户权限管理
- **角色系统**：
  - 基础用户(user)：基本功能访问权限
  - 高级用户(premium)：扩展功能访问权限
  - 管理员(admin)：全部功能和用户管理权限
- **权限控制**：
  - 前端路由级别的权限检查
  - API接口级别的权限验证
  - 动态权限验证支持实时权限变更

#### FR-004: 安全特性
- **防暴力破解**：
  - IP级别的访问频率限制
  - 账户级别的失败次数限制
  - 渐进式延时惩罚机制
- **安全审计**：
  - 登录成功/失败日志记录
  - 异常登录行为监控
  - 安全事件追踪

### Non-Functional Requirements

#### NFR-001: 性能要求
- **响应时间**：
  - 登录请求响应时间 < 2秒
  - 权限验证响应时间 < 500ms
  - JWT验证处理时间 < 100ms
- **并发支持**：
  - 支持同时1000个并发登录请求
  - 支持5000个用户同时在线

#### NFR-002: 安全要求
- **密码安全**：
  - 密码至少8位，包含大小写字母、数字、特殊字符
  - 使用bcrypt进行密码哈希存储
  - JWT使用HMAC-SHA256签名算法
- **传输安全**：
  - 全站HTTPS加密传输
  - 敏感信息不在日志中记录

#### NFR-003: 可用性要求
- **用户体验**：
  - 登录界面简洁清晰，符合现代Web设计标准
  - 错误信息友好易懂，指导用户正确操作
  - 支持记住登录状态，减少重复登录
- **兼容性**：
  - 支持主流浏览器（Chrome 90+, Firefox 90+, Safari 14+, Edge 90+）
  - 响应式设计，适配不同屏幕尺寸

#### NFR-004: 可维护性要求
- **代码质量**：
  - TypeScript强类型约束
  - ESLint代码规范检查
  - 单元测试覆盖率 > 80%
- **监控运维**：
  - 登录成功率监控
  - 系统错误率监控
  - 性能指标监控

## Success Criteria

### 关键指标

#### 用户体验指标
- **登录成功率** ≥ 99.5%
- **平均登录时间** ≤ 2秒
- **用户登录转化率** ≥ 95%（从访问登录页到成功登录）

#### 安全指标
- **暴力破解防护有效率** = 100%（所有暴力破解尝试被成功阻止）
- **未授权访问事件** = 0起/月
- **安全漏洞** = 0个（通过安全审计验证）

#### 性能指标
- **系统并发处理能力** ≥ 1000 登录请求/秒
- **JWT验证性能** ≤ 100ms平均响应时间
- **系统可用性** ≥ 99.9%

#### 业务指标
- **日活跃用户数** ≥ 80%（5000用户中4000人日活）
- **用户会话时长** ≥ 30分钟平均
- **权限升级转化率**：从基础用户到高级用户 ≥ 15%

### 验收标准

#### 功能验收
- [ ] 用户可以使用有效邮箱和密码成功登录
- [ ] 无效凭据登录会显示明确错误信息
- [ ] 连续登录失败会触发账户保护机制
- [ ] JWT token可以正确验证用户身份和权限
- [ ] 不同角色用户可以访问对应权限的功能
- [ ] 会话过期会自动跳转到登录页面
- [ ] 用户可以正常退出登录

#### 安全验收
- [ ] 密码在传输和存储中都已加密处理
- [ ] JWT token包含正确的签名和有效期
- [ ] 暴力破解尝试会被成功阻止
- [ ] 跨站请求攻击会被有效防护
- [ ] 敏感信息不会在前端暴露

#### 性能验收
- [ ] 在正常负载下，登录响应时间 < 2秒
- [ ] 支持1000并发登录请求不出现错误
- [ ] JWT验证处理时间 < 100ms

## Constraints & Assumptions

### 技术约束
- **前端框架**：必须使用Next.js 15 + React 19 + TypeScript
- **UI框架**：必须使用Tailwind CSS v4 + shadcn/ui组件库
- **后端框架**：必须使用NestJS 11 + TypeScript
- **认证方案**：必须使用JWT认证机制
- **部署环境**：Vercel平台部署

### 业务约束
- **用户注册**：不支持自主注册，用户账户由管理员创建
- **密码重置**：当前版本不支持找回密码功能
- **多因素认证**：当前版本不支持MFA
- **单点登录**：当前版本不支持第三方SSO集成

### 假设条件
- 用户具备基本的Web应用使用能力
- 企业用户主要在办公环境使用，网络环境稳定
- 用户账户信息由系统管理员维护和管理
- 5000用户规模在未来1年内不会超出预期

### 资源约束
- 开发周期：4周完成核心功能开发
- 开发团队：2名全栈开发工程师
- 测试周期：1周完成功能测试和安全测试

- **代码规范**：ESLint + Prettier
- **类型检查**：TypeScript编译器
- **测试框架**：Jest + React Testing Library
- **构建工具**：Next.js内置Turbopack

### 内部依赖

#### 后端API依赖
- **认证接口**：`POST /auth/login` - 用户登录验证
- **用户信息接口**：`GET /user/profile` - 获取用户基本信息
- **权限验证接口**：JWT token验证机制
- **会话管理**：Token刷新和撤销功能

#### 共享代码依赖
- **shared包**：用户类型定义、API接口类型
- **通用工具**：错误处理、日志记录、配置管理

#### 数据存储依赖
- **用户数据**：依赖后端数据库中的用户表
- **会话存储**：依赖Redis或内存存储管理会话状态
- **日志存储**：依赖日志系统记录认证事件

### 第三方服务依赖

#### 部署环境
- **Vercel**：前端应用部署平台
- **环境变量**：JWT_SECRET、API端点配置
- **域名服务**：HTTPS证书和域名解析

#### 监控服务（可选）
- **错误追踪**：Sentry或类似服务
- **性能监控**：Vercel Analytics
- **日志聚合**：云端日志服务

### 依赖风险评估

#### 高风险依赖
- **JWT_SECRET密钥**：密钥泄露会导致认证系统完全失效
- **后端认证API**：后端服务不可用直接影响登录功能
- **数据库连接**：数据库故障导致用户验证失败

#### 风险缓解策略
- 实施密钥轮换机制，定期更新JWT密钥
- 设计降级方案，后端故障时提供友好的错误提示
- 实现健康检查，监控关键依赖服务状态
- 建立回滚机制，确保在部署失败时快速恢复

### JWT Payload结构
```typescript
interface JWTPayload {
  userId: string;           // 用户唯一标识
  email: string;           // 用户邮箱
  name: string;            // 用户姓名
  role: 'admin' | 'premium' | 'user';  // 用户角色
  permissions: string[];   // 权限列表
  iat: number;            // 签发时间
  exp: number;            // 过期时间
}
```
